# Foliohush

**留一点安静，写下下一个想法。**

Foliohush 是一款本地优先的写作应用，采用留白充足的阅读式布局和 React 富文本编辑器。写下草稿，保存重要版本，再以 JSON、Markdown 或 HTML 格式带走你的文字。

## 现有功能

- **专注的写作空间：** 文档列表、按标题搜索、标题大纲、专注模式、字词计数和预计阅读时间。
- **就近排版：** 选中文字即可设置粗体、斜体、删除线、高亮、行内代码和链接。使用块类型菜单，或在空段落输入 `/`，插入标题、列表、引用、代码块和分隔线。
- **手动版本快照：** 为草稿保存带名称的快照。恢复旧版本前，会先将当前草稿保存为恢复快照。每篇文档保留最新的 12 个快照。
- **浏览器本地自动保存：** 文档与快照存储在 `localStorage` 中。保存失败会显示提示；遇到损坏或不兼容的数据时，不会悄悄覆盖原始数据；写入前会比较预期存储内容，并在支持时使用 Web Locks 协调标签页；检测到冲突会暂停保存。
- **可携带的文件：** JSON 保存文档和快照；Markdown 与 HTML 适合阅读或后续发布。通过校验的 JSON 始终导入为新文档。保存失败时可使用紧急 TXT 导出保留当前编辑器中的文字。
- **可复用的源码组件：** `FolioEditor` 提供带类型的回调、占位文字和可编辑／只读模式。

这是一个应用仓库，尚未作为 npm 组件包发布。应用界面目前为英文；本文件是使用文档的中文版本。

## 本地运行

需要 **Node.js 22.12 或更高版本**及 npm。仓库中的 CI 工作流使用 Node 24。

在仓库目录中运行：

```sh
npm ci
npm run dev
```

打开 Vite 打印的本地地址，通常为 `http://127.0.0.1:5173`。无需账号、API 密钥或后端。安装依赖需要网络；字体通过 Fontsource 本地打包，运行时无需访问字体 CDN。

构建生产版本并在本地检查：

```sh
npm run build
npm run preview
```

产物位于 `dist/`，可以交给静态网站服务器托管。`npm run preview` 仅用于检查构建结果，不是生产服务器。协议、主机名或端口改变后，浏览器会使用另一份存储空间。

## 开始写作

1. 点击 **New document**，为文档输入标题。
2. 开始写作；选中文字后会出现浮动格式栏。
3. 在空段落输入 `/`，按名称筛选块类型。使用方向键选择、Enter 插入、Escape 关闭。
4. 大幅修改前打开 **Snapshots**，输入名称并点击 **Save snapshot**。
5. 通过 **Export → Full-fidelity backup** 下载当前文档及其快照的 JSON 备份。需要备份多篇文档时，请逐篇导出。
6. 使用 **Import a JSON backup** 将备份导入为独立的新草稿。

| 操作         | 快捷键             |
| ------------ | ------------------ |
| 粗体         | Ctrl/⌘ + B         |
| 斜体         | Ctrl/⌘ + I         |
| 撤销         | Ctrl/⌘ + Z         |
| 切换专注模式 | Ctrl/⌘ + Shift + F |
| 打开块菜单   | 在空段落输入 `/`   |

计数按空白字符分词，阅读时间按每分钟约 220 个词估算，最少显示 1 分钟。对于中文等不依赖空格分词的语言，这些数字并不准确。

## 务必保存浏览器之外的副本

**浏览器存储不是备份。清除网站数据会删除草稿和快照。应用没有账号、云同步或服务端恢复功能。** 不同浏览器、用户配置、设备、主机名或端口拥有各自的工作区。隐私浏览和浏览器的存储策略也可能影响数据保留。

- 定期将重要文档导出为 JSON，并将文件保存到自己控制的位置。导出针对当前文档，不包含整个文档库。
- 快照与草稿共用浏览器存储，无法防范设备丢失或网站数据被清除。保存第 13 个快照时，最旧的快照会被移除；恢复操作产生的快照也计入这 12 个名额。
- 如果看到 **Not saved** 或存储警告，请在关闭或刷新页面前导出当前内容。未保存时可通过 **Export → Emergency plain text** 下载当前文字的 TXT 文件；它不包含格式和快照。应用不保证自动重试已暂停的保存操作。
- 避免在多个标签页同时编辑同一工作区。应用写入前会检查存储内容是否仍与上次读取或保存的内容一致，并在可用时通过 `navigator.locks` 串行协调标签页。没有 Web Locks 时，仅进行乐观比较，仍可能出现并发写入竞态。检测到冲突会暂停保存，不会自动合并。
- 已加载的页面可以在断网后继续写作；应用没有 Service Worker，也不是可安装的 PWA，因此无法保证离线打开或刷新托管页面。
- 浏览器中的文档和下载的备份没有应用级加密。能够访问浏览器配置或文件的软件可能读取其中内容。

## 范围与限制

Foliohush 面向**以文字为主的写作**，支持段落、1–3 级标题、无序／有序列表、引用、代码块、分隔线和行内格式。当前不支持图片、附件、表格、嵌入内容、多人协作、发布账号、AI 服务或 Markdown／HTML 文件导入。界面也暂不提供删除文档或一次性导出整个工作区的功能。

工作区最多容纳 **50 篇文档**，每篇保留 **12 个快照**。整个工作区的存储数据和每个 JSON 导入／导出文件均限制为 **4 MiB**。浏览器自身的配额可能更低，快照也占用工作区容量。这些是安全上限，不代表接近上限时仍有流畅的编辑性能。

编辑器会在提交修改前校验文档事务，不支持的修改会被拒绝并显示提示。JSON 导入仅接受版本化的 Foliohush 格式，并校验节点、属性和复杂度。链接仅允许绝对 `http:`、`https:` 和 `mailto:` 地址。这些检查用于降低风险，并不证明链接目标可信。导入时会重新生成文档标识，避免根据文件中的 ID 覆盖已有草稿。

Markdown 无法完整表达所有富文本格式：下划线和高亮会保留文字，但丢失样式；字母或罗马数字列表标记会转换为数字。文档格式支持从 0 开始的有序列表及 `1`、`a`、`A`、`i`、`I` 标记类型，JSON 和 HTML 会保留这些属性。HTML 导出是保留受支持格式、没有应用样式的独立页面。两者都不包含快照，也不能通过应用重新导入。需要可恢复的备份时，请使用 JSON。

## 来源与许可

应用外壳、样式、斜杠菜单、快照流程、校验和导出代码属于本项目。编辑器基于 [Tiptap](https://tiptap.dev) 和 [ProseMirror](https://prosemirror.net)，界面使用 React，构建使用 Vite，图标来自 Lucide，DM Sans 和 Libre Caslon Text 字体由 Fontsource 提供。

设计参考了宽松、简洁的编辑式写作界面。Foliohush 与 Medium 无关联，不使用其品牌，也不将上游编辑器技术宣称为原创。
